# Angel & Gold

## الملفات
- `index.html` — الموقع الأساسي (الرئيسية، التصميمات، الطلب، الشات بوت)
- `admin.html` — لوحة التحكم (محمية بجلسة دخول حقيقية من السيرفر)
- `login.html` — صفحة تسجيل الدخول
- `middleware.js` — بيمنع أي حد يفتح admin.html من غير جلسة دخول صحيحة (بيشتغل على سيرفر Vercel قبل ما الصفحة توصل للمتصفح خالص)
- `api/login.js` — بيتأكد من الباسورد على السيرفر، وبيدي كوكي جلسة آمنة (HttpOnly)
- `api/logout.js` — بيمسح الجلسة

## الأمان دلوقتي (فرق عن المرحلة اللي فاتت)
- الباسورد بقى **مش موجود في أي كود بتاع المتصفح خالص**. مخزّن كـ Environment Variable على السيرفر بس.
- المقارنة بتحصل على السيرفر (Vercel Edge Function)، مش في الـ JavaScript اللي بيشتغل عند الزائر.
- الكوكي اللي بتثبت إنك داخلة HttpOnly (يعني JavaScript في المتصفح نفسه مينفعش يقراها، بيقلل مخاطر XSS) وSecure (بترسل على HTTPS بس) وSameSite=Strict.
- `admin.html` نفسه **متمنوع يوصل للمتصفح** أصلاً من غير جلسة صحيحة - مش بس المحتوى مخفي، الصفحة نفسها بترجع Redirect لصفحة الدخول.

## خطوات الرفع على GitHub وVercel

### 1) فكي الـ ZIP وارفعيه على GitHub
```
git init
git add .
git commit -m "Angel & Gold"
git branch -M main
git remote add origin <رابط الريبو بتاعك على GitHub>
git push -u origin main
```

### 2) اربطي الريبو بـ Vercel
- ادخلي vercel.com، سجلي دخول، Add New Project، اختاري الريبو.
- Vercel هيكتشف الملفات لوحده (مفيش Build Command مطلوب، الموقع كله Static + Edge Functions).

### 3) أهم خطوة - حطي الباسورد الحقيقي
- في إعدادات المشروع على Vercel: **Settings > Environment Variables**
- ضيفي متغير اسمه `ADMIN_PASSWORD` وقيمته الباسورد الحقيقي بتاعك (اختاري باسورد قوي، مش سهل حد يخمنه)
- اعملي Redeploy بعد ما تضيفي المتغير عشان يتفعّل

### 4) جربي
- افتحي `your-project.vercel.app` → الموقع العادي
- افتحي `your-project.vercel.app/admin.html` → المفروض توديكي لصفحة تسجيل الدخول تلقائي
- اكتبي الباسورد اللي حطيتيه في Vercel → تدخلي على لوحة التحكم

## البيانات (التصميمات والطلبات)
لسه متخزنة في localStorage بتاع المتصفح، ومشتركة بين index.html وadmin.html طالما على نفس الدومين.
دي نقطة لازم تتحل قبل ما تشتغلي بفلوس حقيقية: لو مسحتي بيانات المتصفح أو فتحتي من جهاز تاني، الطلبات المحفوظة هتتصفر.
الخطوة الجاية المنطقية: ربط قاعدة بيانات حقيقية (Supabase مثلاً) بدل localStorage.

## لسه ناقص عشان يبقى جاهز 100% لعملاء حقيقيين
- قاعدة بيانات حقيقية بدل localStorage (Supabase أو غيره)
- الباسورد ده لسه بسيط (باسورد واحد لكل الإدارة). لو محتاجة أكتر من شخص يدخل بصلاحيات مختلفة، محتاجة نظام Users حقيقي.
- Rate limiting على /api/login عشان حد ميحاولش يخمن الباسورد بالتكرار
